# Book Manga Shop API

Backend API интернет-магазина книг и манги. Проект построен на Laravel 13, PHP 8.3+ и MySQL; аутентификация API выполняется через Laravel Sanctum Personal Access Tokens.

Проект предоставляет REST API для каталога книг и манги, регистрации и входа покупателей, заказов, отзывов и административного управления.

## Для преподавателя

- Интерактивная документация API с описаниями, примерами запросов и ответов: [Book Manga Shop API в Postman](https://documenter.getpostman.com/view/58918843/2sBYHaMwaq).
- Коллекция Postman с автотестами (73 запроса, папки в порядке прогона) и шаблон окружения без паролей — в `docs/postman/`. Импортируйте оба файла, заполните `admin_password` и `buyer_password` и запустите **Run collection**.
- Ручные тест-кейсы и подтверждения выполнения находятся в `docs/evidence/`.
- Feature-тесты запускаются командой `php artisan test`; для последнего локального запуска: **54 теста, 222 проверки**.
- Тестовая среда использует SQLite в памяти (`phpunit.xml`), фабрики и `RefreshDatabase`; рабочая MySQL-база не очищается тестами.
- API-запросы и события заказов журналируются в `storage/logs/laravel.log`. Пароли и Bearer-токены не записываются.


## Требования

- PHP 8.3 или новее с расширениями, необходимыми Laravel и PDO MySQL.
- Composer.
- MySQL 8.x (или совместимая версия).
- Git.

## Локальный запуск на Windows

Откройте PowerShell в каталоге репозитория и выполните:

```powershell
composer install
Copy-Item .env.example .env
```

Создайте пустую базу MySQL с именем `book_manga_api` через используемый локальный сервер БД или клиент MySQL. Затем укажите в `.env` свои локальные настройки подключения:

```dotenv
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=book_manga_api
DB_USERNAME=root
DB_PASSWORD=
```

Значения выше — пример для локальной разработки. Если MySQL слушает другой адрес или порт, укажите фактические значения. `.env` индивидуален для каждой машины и не должен коммититься или отправляться в репозиторий.

Продолжите настройку и запустите сервер:

```powershell
php artisan key:generate
php artisan migrate --seed
php artisan serve
```

Сидирование добавляет каталог из 35 товаров (25 томов манги и 10 книг) с обложками по ссылкам на сайты издательств VIZ Media и «Азбука», категории-жанры («Сёнэн», «Тёмное фэнтези», «Комедия», «Триллер», «Драма», «Сборники рассказов», «Классика», «Роман воспитания», «Антиутопия», «Приключения», «Философская сказка»), демо-аккаунты покупателя и администратора, а также отзывы. Тип издания (книга или манга) хранится отдельно в поле `format`, поэтому категории его не дублируют.

Все сидеры используют `updateOrCreate`, поэтому на уже заполненной базе можно выполнить `php artisan db:seed` без очистки: демо-товары перейдут в жанры, а старые категории «Манга» и «Книги» удалятся, если в них не осталось товаров. После запуска API доступен по адресу `http://127.0.0.1:8000`; проверка соединения с БД: `GET http://127.0.0.1:8000/api/health`.

Если миграции уже применены, достаточно запустить `php artisan serve`. Не используйте `migrate:fresh` на базе с нужными данными: эта команда удаляет и создаёт таблицы заново.

## Подключение фронтенда

Для запросов указывайте базовый URL API, заканчивающийся на `/api`, например:

```text
http://127.0.0.1:8000/api
```

Если фронтенд запускается на другом компьютере, запустите Laravel на компьютере с API так:

```powershell
php artisan serve --host=0.0.0.0 --port=8000
```

Вместо `127.0.0.1` во фронтенде укажите LAN-IP компьютера с backend, например `http://192.168.1.25:8000/api`. Компьютеры должны находиться в доступной друг другу сети; если Windows Firewall блокирует соединение, разрешите входящие подключения к порту 8000. База данных остаётся на компьютере, где запущен backend, и фронтенду напрямую подключаться к MySQL не нужно.

Для защищённых запросов передавайте токен из ответа регистрации или входа в заголовке:

```http
Authorization: Bearer <access_token>
Accept: application/json
Content-Type: application/json
```

`Content-Type` нужен для запросов с JSON-телом. Регистрация всегда создаёт пользователя с ролью `buyer`; публичного API для выдачи роли `admin` нет. Для административных функций нужен пользователь с ролью `admin`; порядок локальной настройки описан в разделе «Учётные записи для ручной проверки». Не помещайте рабочие пароли и токены в исходный код, README или общий экспорт Postman.

Для локальной разработки CORS разрешает origin, указанный в `CORS_ALLOWED_ORIGIN` (по умолчанию `http://localhost:5173`). Cookie-аутентификация не используется (`supports_credentials=false`); API использует Bearer-токены.

## Основные эндпоинты

| Метод | Путь | Доступ | Назначение |
|---|---|---|---|
| `GET` | `/api/health` | Публичный | Проверка API и подключения к БД |
| `POST` | `/api/auth/register` | Публичный | Регистрация покупателя |
| `POST` | `/api/auth/login` | Публичный | Вход; возвращает Bearer-токен |
| `POST` | `/api/auth/logout` | Токен | Отзыв текущего токена |
| `GET` | `/api/user` | Токен | Данные текущего пользователя |
| `GET` | `/api/products` | Публичный | Каталог с фильтрами и пагинацией |
| `GET` | `/api/products/{product}` | Публичный | Карточка товара |
| `GET` | `/api/products/{product}/reviews` | Публичный | Отзывы о товаре |
| `POST` | `/api/products/{product}/reviews` | Токен | Создать отзыв; один отзыв пользователя на товар |
| `GET` | `/api/categories` | Публичный | Категории-жанры; `formats` — типы опубликованных товаров в жанре (`book`, `manga`) |
| `GET` | `/api/orders` | Токен | Заказы текущего пользователя; для администратора — все заказы, с `?mine=1` — только свои |
| `GET` | `/api/favorites` | Токен | Избранное текущего пользователя (у каждого своё) |
| `PUT`, `DELETE` | `/api/favorites/{product}` | Токен | Добавить товар в избранное / убрать из избранного (204) |
| `POST` | `/api/orders` | Токен | Создать заказ |
| `GET` | `/api/orders/{order}` | Токен | Получить заказ (владелец или администратор) |
| `PUT`, `PATCH` | `/api/orders/{order}` | Токен | Изменить имя, адрес или телефон своего заказа, пока статус `new`; администратор — пока заказ `new` или `paid` |
| `POST` | `/api/orders/{order}/cancel` | Токен | Отменить свой заказ в статусе `new` (остатки возвращаются на склад); оплаченный или отправленный — 409 |
| `GET`, `POST` | `/api/admin/categories` | Администратор | Список категорий / создать категорию |
| `GET`, `PUT`, `PATCH`, `DELETE` | `/api/admin/categories/{category}` | Администратор | Просмотр, изменение и удаление категории |
| `GET`, `POST` | `/api/admin/products` | Администратор | Список товаров / создать товар |
| `GET`, `PUT`, `PATCH`, `DELETE` | `/api/admin/products/{product}` | Администратор | Просмотр, изменение и удаление товара |
| `GET` | `/api/admin/reports/orders` | Администратор | Сводный отчёт по заказам и продажам (продажи — без отменённых заказов) |
| `PATCH` | `/api/admin/orders/{order}/status` | Администратор | Изменить статус заказа согласно разрешённым переходам |

Все пути в таблице указаны относительно базового URL API. Например, полный адрес каталога: `http://127.0.0.1:8000/api/products`.

### Фильтры каталога

`GET /api/products` поддерживает параметры:

- `search` — поиск по названию и автору;
- `category_id` — идентификатор категории;
- `format` — `book` или `manga`;
- `min_price`, `max_price` — диапазон цены;
- `in_stock` — фильтр наличия (`true`/`false`);
- `sort` — `title`, `price`, `created_at`, `rating` или `popular`;
- `direction` — `asc` или `desc`;
- `per_page` — размер страницы от 1 до 100 (по умолчанию Laravel).

Пример: `GET /api/products?format=manga&min_price=100&in_stock=true&sort=price&direction=asc&per_page=12`.

### ИИ-рекомендации

`POST /api/ai/recommendations` подбирает опубликованные товары в наличии по предпочтениям пользователя. Нужен Bearer-токен; endpoint доступен авторизованным покупателям и администраторам. На маршрут действует ограничение частоты запросов — 5 запросов в минуту.

Пример тела запроса:

```json
{
  "preferences": "Короткая манга в жанре фэнтези и приключений",
  "format": "manga",
  "max_price": 500,
  "limit": 3
}
```

`preferences` — обязательная строка длиной от 3 до 500 символов. Параметры `format` (`book` или `manga`), `max_price` (не менее 0.01) и `limit` (от 1 до 5) необязательны.

Пример успешного ответа (`200`; поля товара сокращены для наглядности):

```json
{
  "data": {
    "summary": "Подборка по вашим предпочтениям.",
    "recommendations": [
      {
        "product": {
          "id": 2,
          "title": "Название товара",
          "format": "manga",
          "price": "286.75"
        },
        "reason": "Подходит по жанру и формату."
      }
    ]
  },
  "meta": {
    "cached": false
  }
}
```

Коды ответа: `401` — отсутствует или недействителен токен; `422` — ошибки валидации; `429` — превышен лимит запросов; `503` — сервис ИИ временно недоступен. Если каталог не содержит подходящих товаров, API возвращает `200` с пустым массивом рекомендаций.

Для работы функции задайте `GEMINI_API_KEY` в локальном `.env`. Модель настраивается через `GEMINI_MODEL`; в `.env.example` указано значение по умолчанию `gemini-3.1-flash-lite`. Не публикуйте ключ в репозитории, Postman-коллекции или клиентском приложении. Предпочтения передаются внешнему сервису Gemini, поэтому не включайте в них персональные и конфиденциальные данные.

### Создание заказа

Передавайте идентификаторы товаров и количество. Цены берутся backend из каталога, поэтому фронтенд не должен отправлять цену:

```json
{
  "shipping_name": "Имя получателя",
  "shipping_address": "Адрес доставки",
  "phone": "+7 700 000 00 00",
  "delivery_method": "courier",
  "payment_method": "kaspi",
  "items": [
    { "product_id": 1, "quantity": 2 }
  ]
}
```

`phone` — необязательный телефон (цифры, пробелы, дефисы, скобки, необязательный `+`). `delivery_method`: `courier` (по умолчанию), `point` или `pickup`; `payment_method`: `card` (по умолчанию), `kaspi` или `cash` — оплата при получении. Стоимость доставки считает сервер (`config/shop.php`): самовывоз бесплатно, курьер и пункт выдачи — 1 500 ₸, бесплатно при сумме товаров от 15 000 ₸. В ответе заказа есть `items_total`, `delivery_price` и `total` (товары + доставка).

Идентификаторы товаров в одном заказе должны быть уникальны; количество для одной позиции — от 1 до 99. Если товара недостаточно или он не опубликован, API возвращает 409 Conflict. Заказ и остатки не изменяются частично. Создание заказа выполняется транзакционно.

Администратор меняет состояние заказа через `PATCH /api/admin/orders/{order}/status`: `new` → `paid` или `cancelled`, `paid` → `shipped`, `shipped` → `delivered`. Завершённые и отменённые заказы дальше не переводятся.

### Формат ответов и ошибки

Успешные ответы ресурсов обычно находятся в поле `data`; списки содержат стандартные `links` и `meta` пагинации Laravel. Основные коды ответа:

- `200` — успешно;
- `201` — ресурс создан;
- `204` — успешно удалён, тело ответа пустое;
- `401` — отсутствует или недействителен токен;
- `403` — нет прав для действия;
- `404` — ресурс не найден или недоступен;
- `409` — нехватка товара на складе, недопустимый переход статуса заказа или иной конфликт состояния;
- `422` — ошибки валидации;
- `429` — превышен лимит запросов (вход и регистрация — 10 в минуту, ИИ-рекомендации — 5 в минуту).


## Тестирование

Тесты используют отдельную SQLite-базу в памяти, заданную в `phpunit.xml`. Для выполнения тестов нужна установленная PHP-зависимость SQLite (`pdo_sqlite`):

```powershell
php artisan test
```

Тесты покрывают регистрацию и вход, роли и доступ, каталог и фильтры, оформление заказа и остатки, отзывы, административные сценарии и ИИ-рекомендации. Вызовы Gemini в тестах подменяются через `Http::fake()`, поэтому тестирование не требует ключа API или доступа к внешней сети. Тесты создают данные фабриками и очищают тестовую БД между запусками.

## Учётные записи для ручной проверки
ЭТО УЧЕБНЫЕ ДАННЫЕ!!!
Администратор: admin@example.test / DemoAdmin!2026
Покупатель: buyer@example.test / DemoBuyer!2026
Коллекция Postman не содержит готовых паролей и токенов. Создайте покупателя через `POST /api/auth/register`, указав собственные имя, email и пароль; полученный токен используйте как Bearer Token. Для административных запросов требуется отдельный пользователь с ролью `admin`. В локальной учебной БД роль можно назначить созданному пользователю командой Tinker:

```powershell
php artisan tinker --execute="App\Models\User::where('email', 'your-admin@example.com')->update(['role' => 'admin']);"
```

После этого выполните вход через `POST /api/auth/login` и используйте выданный токен. Не используйте личные пароли или токены в README, репозитории или опубликованном окружении Postman.
